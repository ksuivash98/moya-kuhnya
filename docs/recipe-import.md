# Подключение рецептов по фото и тексту

Код реализован, но живое распознавание заработает только после развёртывания Edge Function и настройки серверного ключа. В облачной среде ключей и доступа к управлению вашим Supabase нет. Платных запросов при разработке не было. Загрузка сайта на GitHub Pages не развёртывает функции и не применяет SQL.

## 1. Один новый SQL-файл

Если 001–008 уже успешно выполнены, повторять их не нужно.

1. Откройте [содержимое 009](https://raw.githubusercontent.com/ksuivash98/moya-kuhnya/main/supabase/migrations/202610290009_recipe_import.sql).
2. Скопируйте **весь код**, не название файла и не ссылку: Ctrl+A → Ctrl+C.
3. Supabase → SQL Editor → новый запрос. Вставьте код и нажмите Run.
4. При предупреждении об автоматическом включении RLS выберите Run without RLS: файл сам включает RLS и определяет политики. Дождитесь `Success. No rows returned`.

Создаётся только `recipe_import_requests` и функция `reserve_recipe_import`; рецепты, запасы и деньги не меняются. В таблице хранятся тип источника, SHA-256, время согласия/запроса, статус и распознанный результат. Оригинальные текст и фото не сохраняются на нашем сервере. Результат доступен только автору при действующем членстве в семье. Чужие и детские аккаунты не могут запускать распознавание. Взрослый не получает чужую личную историю даже внутри одной семьи.

## 2. Развёртывание функции

На компьютере нужны Node.js и Git. Откройте терминал в локальной копии репозитория. Если копии ещё нет:

```sh
git clone https://github.com/ksuivash98/moya-kuhnya.git
cd moya-kuhnya
```

Если она уже есть, сначала сохраните свои локальные изменения и выполните `git pull --ff-only`. Затем:

```sh
npx supabase login
npx supabase functions deploy recipe-import --project-ref YOUR_PROJECT_REF --no-verify-jwt --use-api
```

Замените `YOUR_PROJECT_REF` на идентификатор проекта из Settings → General (также это часть Project URL перед `.supabase.co`). Открывшийся вход Supabase подтвердите своим аккаунтом. Команда передаёт исходники функции и общий модуль `_shared`; не нужно вставлять TypeScript в SQL Editor. Флаг `--no-verify-jwt` выключает только проверку шлюза: сама функция проверяет реальный JWT через `auth.getUser()`, затем роль/членство через серверную SQL-функцию. Анонимного распознавания нет.

При недоступности команды сначала обновите CLI (`npx supabase@latest ...`). Развёртывание не включает платные запросы: по умолчанию `AI_IMPORT_ENABLED` выключен.

## 3. Серверные настройки и расходы

Сначала владелец выбирает модель OpenAI, проверяет её текущий тариф, поддержку **изображений, Responses API и строгого JSON Schema** и устанавливает лимиты расходов в аккаунте провайдера. Подписка ChatGPT не заменяет оплату API. На этапе разработки модель и платный тариф автоматически не выбирались.

Supabase → Edge Functions → Secrets → Add new secret (названия пунктов могут отличаться). Задайте:

| Имя | Значение |
| --- | --- |
| `AI_PROVIDER_KEY` | Ваш серверный API-ключ OpenAI |
| `AI_IMPORT_MODEL` | Идентификатор выбранной совместимой модели |
| `APP_ORIGIN` | `https://ksuivash98.github.io` |
| `AI_IMPORT_ENABLED` | Сначала `false`; `true` только после согласования тарифа и лимитов |

`AI_PROVIDER_KEY` общий с ранее подготовленным помощником; его изменение затронет обе функции, если помощник включён. `AI_IMPORT_ENABLED` управляет только импортом, а `AI_ENABLED` — только помощником. Системные `SUPABASE_URL`, `SUPABASE_ANON_KEY` и `SUPABASE_SERVICE_ROLE_KEY` доступны Edge Functions автоматически; их не нужно переносить в GitHub Variables или VITE. Ключ не присылайте в чат, не вставляйте в браузерный код/SQL и не коммитьте. Шаблон `.env.example` содержит только имена, без реальных значений.

После настройки Secrets обновите сайт. GitHub Actions продолжает публиковать браузерные изменения при push в main. При следующем изменении **серверного** кода повторно выполните команду deploy; push сам этого не делает.

## 4. Проверка пользователем

1. Войдите взрослым участником → Мои рецепты → Добавить рецепт → Из текста.
2. Вставьте небольшой реальный рецепт, явно разрешите отправку выбранного текста в OpenAI и нажмите «Распознать рецепт».
3. Сравните результат с оригиналом. Нажмите «Проверить и редактировать».
4. Исправьте ингредиенты, единицы, шаги, порции и время. Неизвестные числовые поля остаются пустыми; форма не сохранится, пока они не заполнены. Только явная единица «по вкусу» освобождает ингредиент от количества.
5. Нажмите «Сохранить рецепт». Проверьте его после перезагрузки и у второго члена семьи.
6. Для фото используйте один чёткий снимок рецепта/скриншот. JPEG, PNG, WebP до 20 МБ преобразуются в JPEG до 1600 px; для запроса итоговый файл должен быть не больше 3 МБ. HEIC предварительно экспортируйте в JPEG. Исходник не становится обложкой блюда: её можно загрузить отдельно в форме.

Для восстановления после закрытия окна: снова откройте импорт → «Мои последние распознавания». Показываются до пяти ваших готовых результатов в этой семье, без нового платного вызова. Черновик после перехода к редактированию сохраняется в IndexedDB отдельно от ручного черновика и восстанавливается при обновлении той же страницы. После закрытия формы его можно открыть через «Мои черновики после распознавания» в окне импорта (последние пять на этом устройстве). Оригинал, ещё не отправленный на распознавание, живёт только в открытом окне и при закрытии теряется.

## Гарантии и границы

- Только явно выбранный снимок/текст; семейная книга, медицинские предпочтения, участники и запасы не передаются. `store:false` отключает хранение Response как объекта API; условия технического хранения/обработки самого провайдера определяются его политикой. Не отправляйте личные данные.
- До пяти запусков в сутки на пользователя во всех семьях, граница дня — Екатеринбург. Неудачные запросы тоже учитываются. Блокировка профиля защищает квоту от параллельных вызовов. Ограничение числа запросов не заменяет денежный лимит у провайдера.
- Один идентификатор + один SHA-256 источника: готовый результат возвращается повторно, pending/failed не вызывает ИИ снова. При обрыве сети попробуйте прежний запрос или проверьте историю. «Новый запрос» разрешает отдельный вызов и может снова стоить денег; не используйте его многократно при таймауте.
- Ответ проверяется по строгой схеме, длинам, единицам и числам. Указания внутри источника считаются недоверенными данными. Модель всё равно может ошибиться; окончательную правильность рецепта подтверждает пользователь.
- Отсутствие рецепта, отказ/неполный ответ провайдера, неверный формат или недоступный сервер показывают ошибку и не создают запись рецепта. Запись в книгу идёт через существующий `save_recipe` только после подтверждения формы.
- Сервер хранит распознанные результаты до удаления семьи/профиля или административной очистки. Автоматического TTL/планировщика очистки нет. Не удаляйте сегодняшние журналы для обхода квоты.
- Видео, ссылки, многостраничные наборы фото и фоновое распознавание не реализованы. Офлайн нужен ручной черновик; распознавание требует интернета.

Проверки разработчика: `npm run typecheck`, `npm test`, `npm run build`, браузерные сценарии фото/текста/истории на desktop/mobile и `deno check --node-modules-dir=manual supabase/functions/recipe-import/index.ts`. Платный провайдер в тестах заменён контролируемым ответом; SQL проверяется реальными миграциями в изолированном PGlite. Это не проверка вашего живого Supabase или качества реальной модели.
