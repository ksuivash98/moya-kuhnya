# Моя кухня

Семейное приложение. Реализованы основа, книга рецептов и основные связанные разделы меню, готовки, запасов, заготовок, покупок, бюджета и аналитики. React 19, TypeScript, Vite, Tailwind CSS, Supabase Auth / PostgreSQL, PWA. Интерфейс на русском; молочная, розовая и шалфейная палитра, светлая и тёмная темы, Lucide, адаптивная навигация.

## Что работает

- Все 11 маршрутов, главная страница, настройки, состояния загрузки и ошибок.
- Регистрация с подтверждением почты, вход, выход, восстановление и смена пароля через Supabase.
- Создание и выбор семейных пространств, профиль, одноразовые приглашения на 7 дней, отзыв приглашений.
- Роли: владелец, взрослый, ребёнок. Владелец управляет участниками и разрешением редактирования для ребёнка. Владелец защищён от удаления/понижения.
- Семейная лента из базы, количество участников, обновление по Realtime, при возврате на вкладку, восстановлении связи и раз в минуту.
- PWA-манифест, собственные иконки, service worker и установка через поддерживающий браузер.

- Книга рецептов: CRUD с архивированием, категории, поиск по ингредиентам, сортировки, избранное, порции, приватные фото, пошаговая форма и локальные черновики. [Подключение и ограничения этапа 2](docs/recipes.md).

- Импорт по фото и тексту: распознавание через отдельную Edge Function, предварительный просмотр, редактируемый черновик, явное сохранение и личная история. Требует серверного ключа и включения владельцем. [Пошаговое подключение](docs/recipe-import.md). Видео и ссылки пока не поддерживаются.

Нет демонстрационных пользовательских записей. Все общие изменения сохраняются в Supabase с RLS, версиями и журналами; допустимая офлайн-очередь явно отделена от подтверждённых серверных операций. ИИ-провайдер и фоновые push не подключены. [Актуальное состояние и границы](IMPLEMENTATION_PROGRESS.md), [новые миграции, запуск и ограничения](docs/operations.md).

## Запуск

Нужен Node.js 24 (см. `.nvmrc`).

```sh
npm ci
cp .env.example .env.local
# Заполните .env.local после настройки Supabase ниже
npm run dev
```

Без переменных открывается интерфейс с инструкцией подключения. Сохранение и авторизация не имитируются. Не коммитьте `.env.local`. Используйте существующую рабочую копию; отдельный Git worktree не требуется.

## Настройка Supabase

1. Создайте проект Supabase. В **SQL Editor** выполните `supabase/migrations/202610280001_foundation.sql` целиком **один раз**, затем `supabase/migrations/202610280002_recipes.sql` один раз. Для существующего проекта не повторяйте уже выполненные файлы; затем последовательно примените новые 003–008 по docs/operations.md. Для CLI вместо SQL Editor: `supabase link --project-ref YOUR_REF`, затем `supabase db push`. Не выполняйте оба способа для одной базы.
2. В **Connect / API Keys** получите Project URL и **publishable key** (или legacy `anon`). Заполните `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` в `.env.local`. Это публичные клиентские параметры; доступ к данным защищает RLS. **Никогда** не используйте `service_role`, secret key или ключ ИИ в `VITE_*`.
3. В **Authentication → Providers** включите Email и подтверждение почты. Для публикации настройте собственный SMTP и ограничения отправки писем.
4. В **Authentication → URL Configuration** задайте Site URL сайта. В Redirect URLs добавьте адрес локального запуска и публикации с `/auth/callback` (например, `http://localhost:5173/auth/callback`). Разрешайте конкретные адреса; не используйте широкий production wildcard.
5. Перезапустите `npm run dev`, зарегистрируйтесь, подтвердите почту. Создайте семью в настройках. Если профиль создан до миграции, миграция переносит его из `auth.users`.
6. Владелец создаёт одноразовый код и передаёт его близкому лично. Близкий регистрируется, затем выбирает «У меня есть приглашение». Код хранится на сервере только в виде SHA-256 и не отображается повторно после закрытия/обновления страницы.
7. Проверьте регистрацию/почту, восстановление пароля, вход на втором устройстве и обновление семейной ленты. В Realtime таблицы `family_members` и `family_activity` добавляются миграцией, если публикация `supabase_realtime` существует.

Ключи и URL реального проекта в текущей среде отсутствуют. Подключение к вашему Supabase, доставка писем, межустройственная работа и установка на физических телефонах требуют отдельной проверки после этих шагов. Встроенные SQL-тесты проверяют миграцию и RLS в локальном PostgreSQL-движке; они не заменяют эту проверку.

## Проверки

```sh
npm run typecheck
npm test
npm run build
npx playwright install chromium
npm run test:ui
```

Если Chromium уже установлен: `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:ui`.

SQL-тесты: создание семьи, роли, запрет повышения прав, приглашения/сроки/отзыв, изоляция семей и личных предпочтений, запрет анонимного доступа, сохранение журнала после удаления участника. Для них не нужны Docker и Supabase-ключи: используется PGlite (PostgreSQL в WASM), роль `authenticated` без обхода RLS и тестовые служебные таблицы Auth/Storage с `auth.uid()`; сами RLS и RPC загружаются из миграций.

Playwright проверяет маршруты, мобильный интерфейс, настройку сервиса, темы и полный цикл рецептов поверх SQL-тестового сервера. PWA дополнительно проверяется на production-сборке: manifest, service worker, установка оболочки и офлайн-загрузка. Не проверенные реальные сервисы не считаются пройденными тестами.

## Публикация

```sh
npm ci
npm run build
```

Опубликуйте каталог `dist` на HTTPS-хостинге (Netlify, Vercel, Cloudflare Pages или аналог). Build command: `npm run build`; output: `dist`. Задайте обе `VITE_SUPABASE_*` переменные **перед сборкой**. Для Netlify уже добавлен `netlify.toml`; для других платформ настройте SPA fallback на `/index.html`, включая `/auth/callback`. Для Vercel есть `vercel.json`. Укажите адрес публикации в Supabase Auth. Обновления переменных требуют новой сборки. Публикация не выполняется автоматически без подключённого хостинга.

PWA работает на HTTPS или loopback. На iOS: Safari → «Поделиться» → «На экран Домой». На Android: меню браузера → «Установить приложение». Service Worker кэширует только оболочку и ресурсы. Ранее открытые семейные данные и допустимая очередь хранятся отдельно в IndexedDB пользователя/семьи; запасы и финансы изменяются только онлайн. Подробности — в docs/operations.md.

## Структура

- `src/App.tsx` — оболочка, маршруты, главная, Auth, семьи и настройки.
- `src/recipes/` — модель, серверный клиент, книга, форма, просмотр, фото и черновики.
- `src/components/Modal.tsx` — общее доступное модальное окно.
- `src/supabase.ts` — клиент, проверка конфигурации, русские сообщения ошибок.
- `src/style.css` — дизайн-система, Tailwind, адаптивность, темы.
- `supabase/migrations/` — схема, RLS и транзакционные RPC.
- `tests/` — PostgreSQL и браузерные проверки.
- `docs/architecture.md` — границы этапов, безопасность и дальнейшая архитектура.

Продолжение не требует повторной постановки этапов: фактические результаты и оставшиеся внешние настройки записаны в IMPLEMENTATION_PROGRESS.md.

## GitHub Pages — автоматическая веб-версия

Исходники React нельзя публиковать через «Deploy from a branch / main / root».

1. Откройте **Settings → Pages → Build and deployment → Source** и выберите **GitHub Actions**. Это настройка один раз.
2. Workflow `.github/workflows/pages.yml` запускается при каждом push в `main`: проверяет типы и SQL-тесты, собирает Vite, публикует **dist**. Для повторного запуска: **Actions → Публикация веб-версии → Run workflow → main**.
3. После успешного задания `deploy` адрес: **https://ksuivash98.github.io/moya-kuhnya/**. Публикация может занять несколько минут; её статус доступен в Actions.
4. Для подключения Supabase добавьте публичные `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` в **Settings → Secrets and variables → Actions → Variables**, затем перезапустите workflow. Без них откроется веб-интерфейс с инструкцией подключения.
5. В Supabase Site URL укажите `https://ksuivash98.github.io/moya-kuhnya/`, а Redirect URLs — `https://ksuivash98.github.io/moya-kuhnya/auth/callback`.

Путь проекта задаётся `VITE_BASE_PATH`. Ресурсы, браузерный роутер, manifest и service worker учитывают его. `404.html` позволяет открывать прямые SPA-ссылки: GitHub Pages отвечает HTTP 404, но приложение отображает нужную страницу и сохраняет параметры Auth. На хостингах с полноценным SPA rewrite можно сохранить обычный корневой `npm run build`.

Проверка GitHub Pages локально: `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:pages`. Тестовый сервер эмулирует путь проекта и HTTP 404 без встроенного Vite fallback. Обычные тесты `npm run test:ui` выполняйте отдельно, последовательно: обе проверки собирают `dist`.
